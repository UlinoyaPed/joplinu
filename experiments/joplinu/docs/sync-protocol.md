# 加密增量同步 v1

本实现是独立协议，不读取或覆盖原版 Joplin 同步目录。前台文档引擎、原生云传输和本地事务分离；OSS 与 S3 使用同一对象布局。当前是开发版，真机中文输入、真实 OSS 和大容量资料库仍需分别验收。

## 状态与事务

正文仍是逐笔记 Y.Doc 的 `Y.Text('markdown')`，四种编辑器共用。文件夹和笔记元数据使用独立 Y.Map：标量按字段合并，标签和历史按成员 / 条目保存，删除使用墓碑。并发修改同一个标量时使用 Yjs 的确定性胜出规则；正文不是整篇 Markdown 最后写入覆盖。两个离线移动造成的文件夹循环在投影时确定性解环，不删除内容。

本地元数据快照增加 `sync`：元数据 Yjs 状态、每个文档最后入队的状态向量及摘要、密文上传队列、已处理对象摘要、设备标识和上次同步时间。与正文日志使用现有同一次 SQLite / IndexedDB 事务保存。密码和解密主密钥不写入该快照，也不进入普通日志、配置导出或完整笔记备份。

更新先在本机加密，密文字节、随机对象路径和对应向量先提交本地事务，才允许上传。服务端成功而响应丢失时，重启后使用原路径和原密文恢复队列；读取验证 SHA-256 后才原子确认。删除集不能只依赖状态向量判断，因此同时比较完整 Yjs 状态摘要，避免遗漏纯删除操作。笔记正文和元数据分别生成增量对象，不在每次按键上传整个笔记库。

## 云端布局

```
vaults/<random-vault-id>/
  keys/<random-key-id>.json
  updates/<random-device-id>/<random-object-id>.bin
  snapshots/<random-snapshot-id>/<random-piece-id>.bin
  snapshots/<random-snapshot-id>/index.bin
```

各设备仅写自己的全局随机不可变对象，不用共享可变 head，不依赖 CAS、ETag、版本控制或对象锁。当前不删除远端日志或历史；新设备优先从完整加密恢复快照初始化，再下载其后的更新，没有快照则重放全部更新。不会因长期离线被清理掉必需依赖。分页游标循环、超限对象、未到齐的 Yjs 依赖和重复对象均有明确处理。未完整可见的列表、损坏数据或认证失败不会被当成空仓库覆盖本地。

下载先认证并在独立候选文档中合并，验证文件夹、笔记和附件，再一次性提交应用状态与已处理检查点。组合输入期间延迟合并；异步校验期间本地又发生编辑则拒绝本次提交、稍后重试。远端更新不进入本地撤销来源。

## 密钥与认证

Web Crypto 提供随机 256 位主密钥、PBKDF2-SHA256（随机 128 位 salt，600000 次）和 AES-256-GCM 包裹。恢复码为随机 vault ID 与 key ID，不含主密钥；新设备需要相同云配置、恢复码和密码。会话只保留不可导出的 CryptoKey；退出或锁定后需要重新输入密码。忘记密码无法恢复，须保存独立备份。

每个随机不可变对象路径经 HKDF-SHA256 派生独立 AES-256-GCM 密钥，使用随机 96 位 IV；版本与完整对象路径作为 AAD。云端看不到标题、标签、正文、组织信息、附件或历史，但仍可观察对象数量、大小和访问时序。持有主密钥的设备作为同一信任组，不声称可以证明每次更新来自哪个独立设备。

已处理对象的摘要和存在性保存在本地。远端历史缺失时停止同步；手动“检查远端完整性”重新下载已知对象，检测被替换的字节并认证。离线的独立备份仍是回滚和云端删除的恢复基础；新设备无法仅凭不可信云端证明自己拿到的是全局最新历史。

## 平台、安全与当前范围

SDK 或原生签名请求不进入 renderer。每轮同步固定公开云配置，每次原生请求核对，避免操作中途更换存储目标。系统凭据和同步解密密码相互独立。正式版本只使用 HTTPS 并校验证书。

手动同步、解锁后前台每分钟自动同步、队列恢复、加密恢复快照、完整密文仓库迁移和远端完整性检查已接入应用。后台 WebView 不负责合并。系统后台密文传输与密钥轮换尚未完成；不以连接诊断代替这些能力。

目前元数据 / 本地上传队列仍受原有 40 MiB 事务快照上限约束，单个同步明文对象上限 48 MiB，单轮合并状态安全内存上限 96 MiB。下载增量会按文档合并，完整性检查逐个验证已知对象，不把整套历史密文一直保留在内存。超限停止并保留资料，不截断。后续应把附件、历史、队列和检查点进一步拆为独立数据库表，而不是宣称支持无限容量。

## 恢复快照提交与恢复

“创建恢复快照”先完成当前同步，再逐文档加密完整 Yjs 状态。每个密文分片经持久队列上传并回读校验，最后上传加密索引作为提交标志。索引包含所有分片路径 / 摘要及已覆盖更新的摘要。创建中断只留下未被索引引用的分片，不发布半套快照，不触发历史删除。

新设备只使用完整、认证通过的索引，检查其覆盖的原始日志仍可列举，再验证每个分片并在候选状态中恢复；任何分片缺失或篡改均不替换本地数据。检查点之后的更新仍正常 CRDT 合并。快照不会成为不安全裁剪历史的理由，也不代替离线独立备份。

长期离线设备可能继续修改已永久删除的笔记。删除墓碑记录当时已观察的正文状态向量、删除范围和元数据版本；发现墓碑未覆盖的新插入、纯删除或元数据修改时，将编辑保留到回收站并显示提示，用户可恢复或再次明确删除。快照若不包含该旧正文，自动回查仍保留的认证原始日志补齐依赖，而不是丢弃更新或无限等待。正常删除不会自动复活；再次删除时重新记录已观察版本。

## 云存储迁移

在现有同步库解锁后，设置中填写目标 OSS / S3 配置和完整凭据，选择“迁移并切换”。原生宿主创建短期目标句柄，同时保持源连接；凭据不放入笔记和同步对象。迁移先保存 / 同步本机修改，再复制 vault 前缀下的完整对象集合，包含所有更新、快照分片 / 索引、密钥元数据及不完整快照留下的密文分片，不以当前 Markdown 导出代替同步仓库。

每个源密文对象验证认证及已知摘要，目标只写入缺少的对象，逐个回读确认字节摘要。目标若已有不同内容即停止，不覆盖。结束前重新分页列举源，补齐并发新增对象；源持续变化或对象被删则停止切换。只有完整复制和目标可见性校验通过，才采用目标配置。源仓库和目标既有额外对象始终保留，可在故障后重复迁移。其他设备需更换到相同目标配置，文档模型、主密钥、恢复码和同步核心不变。

内存按单对象限制，不把整仓库汇总为单个 ZIP。当前一次迁移最多 200000 对象，最多补扫三轮；需要源读取 / 列举与目标写入 / 读取 / 列举权限。真实 SeaweedFS 验证了不同前缀间的完整复制、目标冲突保护和额外对象保留；真实 OSS 与其他厂商组合仍需各自验收。

验证复用现有真实 S3 集成套件，仅增加一个数据安全场景：实际 SQLite 事务、两个设备离线相近位置编辑、字段合并、密文不含正文、已提交上传响应丢失、重启恢复原队列、新设备恢复、密码错误、密文篡改及远端对象删除。真实 Electron 界面和 Android 原生桥接证据分别记录。
